# Phase 3 Completion Summary — Backend Model Bootstrapping (Step 1)

Files created: backend/transcription/whisper_service.py (init portion — loads faster-whisper small on CUDA/float16, runs a throwaway transcription to force VRAM residency, exposes init()/is_ready()); backend/audio/vad.py (init portion — loads silero-vad via load_silero_vad() on CPU, confirms it responds on a silent buffer, exposes init()/is_ready(), reserved for find_silence_point()/score_speech_probability() in Phase 4); backend/gloss/ollama_client.py (warm-up portion — POSTs a throwaway prompt to /api/generate, discards the response, exposes warm_up()/is_ready()); backend/lookup/dictionary_loader.py (complete — loads isl_dictionary.json using its confirmed real shape, keyed by English word with {gloss, hamnosys} values; re-indexes by uppercased gloss; validates every HamNoSys token against a 21-token set mirrored from hamnosysMap.js's HAMNOSYS_ACTIONS, excluding and logging any entry with an unrecognized token, per Fallback F); backend/lookup/cislr_index.py (complete — builds the gloss to clip-path index from assets/cislr/prototype.csv, not dataset.csv, per the Phase 2 decision; excludes rows with empty gloss or a clip not yet present under CISLR_CLIPS_DIR); backend/main.py (FastAPI app with a lifespan startup handler running all four components concurrently via asyncio.to_thread, and a /health endpoint).

Also updated: backend/config.py's CISLR_DATASET_PATH now points at prototype.csv instead of dataset.csv, with a comment explaining why, applying the Phase 2 decision.

Cross-boundary signature added: GET /health, no arguments, returns {"status": "ready"|"loading", "components": {"whisper": bool, "vad": bool, "ollama": bool, "dictionary": bool, "cislr": bool}}. This is the only externally callable endpoint so far; the WebSocket boundary is not built until Phase 9.

Ambiguity encountered and resolution: cislr_index.py's success criterion. An empty index (zero cached clips) is expected right now since no real demo vocabulary has been chosen yet (Real Data Rule) — this is treated as a successful build, not a startup failure; only an exception during the build counts as failure. Per-clip "not yet cached" logging was initially at WARNING level for every row, which produced 4764 lines on every startup against the current empty clips folder; changed to DEBUG per-row plus one INFO summary line, so real failures stay visible without being drowned out.

Decisions made that are not explicit in the docs: main.py uses FastAPI's lifespan context manager rather than the older on_event("startup") decorator, since it is the currently supported pattern in the installed FastAPI version and the docs do not mandate either; whisper/vad/ollama each run as their own concurrent thread, while dictionary_loader and cislr_index are bundled into a single fourth thread since both are fast, synchronous, non-GPU file-IO steps.

Verified end to end: ran the real backend; /health returned all five components true; dictionary_loader loaded all 260 real entries with zero exclusions; cislr_index correctly excluded the one known malformed row and all 4764 not-yet-cached clips; Whisper, VAD, and Ollama all warmed up against the real local models. No fabricated data was used.
